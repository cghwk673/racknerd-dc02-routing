## 洛杉矶 DC02 是个什么机房？

DC02 全称 Los Angeles DC02，是 RackNerd 在洛杉矶编号 02 的数据中心，物理位置在 multacom 机房，IP 上游是 AS35916。RackNerd 把它当“优化线路”机房来卖——所谓优化，主要就指上面说的三网回程对接方式，这也是它和普通美国机房的差距所在。

有两件事会影响你的判断。

第一，DC02 整体换过一轮 IP。RackNerd 此前对 DC02 的 IP 做过重新编号，老用户收到过换 IP 邮件。网上流传的测试 IP 204.13.154.3 属于老段，现在未必还在现役；换段之后的复测显示三网表现均衡，TikTok 美区和 ChatGPT 依旧解锁。换句话说，这个机房的 IP 质量会随时间变动，到手后先跑一遍自己关心的解锁测试比较稳妥。

第二，它没有 IPv6。测评显示 DC02 的机器只分配 IPv4，如果你的项目依赖 v6（某些监控、PT 或学术资源场景），这里满足不了。

几份测评还提到 RackNerd 支持多个数据中心、可以在面板里切换 IP，DC02 出了问题不至于只能干等工单。

## 三网回程：电信汇入 163 直连，联通走 4837 对接，移动绕 NTT

结论先放前面：电信回程经 BGP 上游汇入电信 163 骨干（AS4134）直连回国，联通回程经 Level3/Cogent 等 BGP 对接 AS4837 骨干，移动回程走 NTT（AS2914）经东京、台北、香港再回国。

几份公开测评的 traceroute 数据大致是这样：

- 电信：回程从 202.97 骨干回国，端到端延迟广州约 160ms，上海约 134–151ms，北京约 163–192ms（晚高峰）。
- 联通：先走 BGP/Level3/Cogent，再对接联通 4837 骨干。北京约 167–193ms，上海约 186–232ms。
- 移动：全程 NTT，绕行东京和香港，北京约 179–222ms。

这些数字是 traceroute 的端到端耗时，包含国内最后一段，只能当量级参考。趋势倒是稳定：换 IP 前后测的几轮结果一致，说明这套回程结构没有变过。

一句话判断：主力宽带是电信或联通，DC02 在同价位里是能打的选择；移动宽带用户要掂量一下，绕 NTT 的路径晚高峰不一定好受，这类需求去看专门的移动优化线路更合适。

## 性能和硬件：E5 老平台和 Ryzen 平台两条产品线

DC02 上的机器分两代硬件。低价促销套餐用 Intel Xeon E5 老平台（测评机为 E5-2697 v2 @ 2.70GHz），AMD 系列的 DC02 测评机是 Ryzen 9 3900X。

磁盘方面，两台 E5 测评机的 FIO 读写分别在 526 MB/s 和 813 MB/s 左右，对这个价位属于正常偏好水平。网络是 1Gbps 端口，海外测速能跑满，Ryzen 系列套餐标注的是 Premium 带宽（走优质上游）。

Ryzen 那边的跑分差距就比较明显了：DC02 的 AMD 线路测评机（单核分配）Sysbench 单线程 1935 分，Geekbench 5 单核 1067 分。同样跑编译、Docker 这类吃单核的活，Ryzen 系列和 E5 的体验不是一个量级。
